# Gushi A/B 前后对比测试结果

> 测试日期：2026-08-17 | 测试人：肖文宇 | 环境：Docker (gushi-app + postgres)

## 一、测试目的

验证"叙事状态表（SCORE动态状态追踪）+ 知识图谱（DOME MEM）"注入对故事续写一致性的影响。

- **A组（基线）**：关闭记忆注入，用原始 Prompt 连续续写 3 段
- **B组（新方法）**：开启状态表+图谱注入，连续续写 3 段
- 两组共享同一个起始段（桃园结义），各自独立分支，保证公平

## 二、测试环境

| 项 | 值 |
|----|----|
| Docker | gushi-app (healthy) + postgres |
| 数据库 | PostgreSQL（db push 同步 schema） |
| 测试故事 | AB对比·桃园结义（三国·刘备/关羽/张飞/董卓） |
| 预置图谱 | 6 节点 / 5 边（桃园结义关系网） |
| 预置状态表 | 8 个对象（4角色 + 1地点 + 3关系） |
| 续写 | 每组 3 段，AI 模型同配置 |

## 三、量化结果

| 指标 | A组（无注入） | B组（有注入） |
|------|--------------|--------------|
| Prompt 长度 | 1942 字 | 3031 字（+状态表+图谱区块） |
| 续写总字数（3段） | 1194 字 | 1173 字 |
| 图谱积累（续写后） | — | **6 → 27 节点，15 → 31 边** |
| 状态表积累（续写后） | — | **8 → 13 个对象** |

> B 分支续写过程中，知识图谱从 6 节点自动增长到 27 节点、状态表从 8 个对象追踪到 13 个——证明"动态状态追踪 + 知识图谱"在生成链路中真正持续生效。

## 四、生成内容对比（人工一致性分析）

### A组（无注入）3段梗概
1. **段1**：桃园结义盟誓，张飞性急请战。结尾"远处忽有马蹄声疾驰而来"
2. **段2**：一骑飞至报"洛阳急报，董卓挟天子以令诸侯，火烧街市"。张飞欲提矛上马被刘备按住
3. **段3**：又是"忽闻林外马蹄声碎"，涿郡郡吏呈竹简报董卓废帝

**问题：**
- ⚠️ **段2、段3 情节套路重复**——连续两段都用"骑马来报信"推进，且都是"董卓祸乱"内容，缺乏层次
- ⚠️ 段2和段3的信息高度重叠（都是董卓作恶的情报）

### B组（有注入）3段梗概
1. **段1**：张飞请战，刘备劝阻（"兵不过数百，粮不过旬月"），关羽引"齐桓公/汉高帝"典故主张徐图
2. **段2**：涿郡郡吏呈竹简，报董卓废少帝立陈留王
3. **段3**：远处号角呜咽，刘备按剑而起识别"西凉军号"，判断董卓出兵，关羽引"项羽破釜沉舟"

**优点：**
- ✅ **情节层层递进**：战略讨论→情报获取→军情预警，段1/2/3 是因果关系链条，无重复套路
- ✅ **状态驱动行为**：段1刘备"兵不过数百"呼应状态表 goal="兴复汉室"；张飞"目眦欲裂"呼应 mood="激昂"
- ✅ **方位合理性**：段3"西凉军号"来自西北（洛阳方向），符合地理常识
- ✅ **角色一致性**：关羽持续引经据典（忠义/沉稳 traits），刘备仁厚持重，张飞急躁勇猛

### 关键差异总结

| 维度 | A组（无注入） | B组（有注入） | 结论 |
|------|--------------|--------------|------|
| 情节重复 | 段2、3 连续"骑马报信"，套路重复 | 段1/2/3 因果递进 | **B组更好** |
| 状态约束 | 角色行为靠模型自由发挥 | 状态表明确注入 goal/mood/faction | **B组更可控** |
| 关系一致性 | 无矛盾（良好） | 无矛盾 + 图谱关系提示 | **两组都达标** |
| 知识累积 | 无记忆 | 图谱6→27节点自动建 | **B组有增量** |

## 五、结论

1. **记忆注入在生成链路中真正生效**：B 组 Prompt 明确包含状态表+图谱区块（+1089 字），续写过程中记忆系统自动积累（图谱 6→27，状态表 8→13）。
2. **初步观察到一致性改善**：B 组减少了"骑马报信"式套路重复，情节推进更符合角色目标状态，方位/关系更合理。
3. **样本小、主观性强**：单次 3 段对比不足以支撑强结论。建议后续：
   - 扩大样本（每个配置跑 5 个不同故事）
   - 用黄夏薇的 LLM-as-Judge 按五维打分 + 喻荣海人工打分做双轨统计
   - 对"情节重复率""角色状态偏差"做自动化量化（如 n-gram 重复检测、状态表比对）
