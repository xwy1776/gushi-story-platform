# Benchmark 具体实施问题清单

> 项目：古事（Gushi）多分支叙事一致性维护
> 用途：向老师确认论文中“基准贡献”的边界和最低可发表标准
> 日期：2026-10-19

---

## 一、我们准备做成什么

当前论文不建议再把“故事生成平台”作为主要贡献，而是采用 **Benchmark + Pipeline**：

### Benchmark

- **任务**：给定同一分叉点和共享前文，只续写分支 A，检查记忆系统会不会把分支 B 的互斥事实注入分支 A；
- **数据**：20 组冲突分叉，每组两条互斥且均非标准历史的走向；
- **规模**：20 组 × 2 档 × 5 段 × 3 轮，共 600 段；
- **指标**：关键词泄漏率、LLM-as-Judge 泄漏率、二者一致率、人工锚定；
- **统计**：以故事为配对单位，报告配对 t 检验、Bonferroni 校正和逐故事胜负；
- **复现**：公开原始生成文本、判定记录、实验脚本和只重建报告的命令。

### Pipeline

把分支隔离接入现有状态表、图谱和续写管线，作为验证该问题的参考实现。
不主张“提出了全新 Agent 架构”，只说明该问题可以怎样被工程化处理。

---

## 二、希望老师确认的七个问题

| # | 问题 | 我们目前的倾向 |
|---|---|---|
| 1 | 20 组、600 段是否足以支撑一个基准贡献？ | 先以“诊断性小基准”定位，不声称大规模覆盖 |
| 2 | 是否必须继续扩到 30 或 50 组？ | 若审稿口径要求规模，再按同协议扩样；当前优先补外部基线 |
| 3 | 外部对比接受 RAG 基线，还是必须复现 SCORE 或 DOME？ | 先做同数据、同模型、同判定的 embedding top-k RAG |
| 4 | 人工评估最少需要几名标注者？ | 先补第二标注者，对 36 条锚定样本独立复标并报告 Cohen's κ |
| 5 | 图像层不显著时如何处理？ | 建议降级为系统功能，并用构念效度解释逐图指标不能代表跨图一致性 |
| 6 | 数据和代码能否公开？ | 代码与生成文本公开；含 API Key、用户隐私和版权风险的内容除外 |
| 7 | 软著与论文的成果排序如何认定？ | 论文为主，软著同步申请；请确认署名、版本和验收口径 |

## 三、建议的最低可投稿版本

在现有基础上，补齐以下五项即可形成一版完整初稿：

1. **RAG 外部基线**：同一故事、同一模型、同一判定，报告 `none / rag / state / graph / both` 五档；
2. **第二标注者**：独立复标 36 条或更多样本，报告一致率和 κ；
3. **摘要与结论**：明确“问题、基准、两条确认性结论、两条否定性结论”；
4. **参考文献表**：至少覆盖 SCORE、DOME、MemLong、LoCoMo、LongMemEval、HELM、BetterBench、Datasheets；
5. **两张主图**：系统或实验流程图、实验 B 逐故事结果图。

如果老师认为规模仍是风险，则把论文定位明确写成：

> 一个面向多分支叙事的诊断性基准与初步实证研究。

这比把小规模数据包装成“通用大基准”更稳。

---

## 四、RAG 基线的具体实施口径

为避免“随手写个 top-k 就算外部对比”，建议把 RAG 分成三段报告：

1. **索引**：段落切分粒度、embedding 模型、是否保留分支元数据；
2. **检索**：查询构造、`top-k`、相似度阈值；
3. **阅读**：检索结果如何进入 Prompt、长度上限、去重与排序。

对比时保持以下条件不变：

- 同一批 20 组故事；
- 同一续写模型和温度；
- 同样的 5 段 × 3 轮；
- 同样的关键词与 Judge 判定；
- 同样以故事为配对单位做统计。

这样才能回答“外部检索式记忆是否同样会跨分支污染”，而不只是多跑一个模块。

---

## 五、需要老师拍板的事项

最需要明确的是下面三项，因为它们直接决定本周之后的工作排序：

1. **外部对比的最低要求**：RAG 是否足够，是否必须复现论文方法；
2. **基准规模的最低要求**：20 组能否进入投稿，还是必须扩到多少；
3. **成果验收口径**：论文录用、见刊、软著分别在中期和结题中如何认定。

其余实验细节可以在上述三项确定后按周推进。
