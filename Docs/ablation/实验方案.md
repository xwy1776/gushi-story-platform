# 记忆注入消融实验方案

> 项目：古事（Gushi）· 多分支叙事的前后文一致性
> 负责人：肖文宇 ｜ 日期：2026-09-13

---

## 一、实验目的

验证「叙事状态表 + 知识图谱」这套混合记忆注入，对故事续写的**前后文一致性**是否有可量化的提升，并拆解两个模块各自的贡献。

回答三个问题：

1. 加了记忆注入，一致性是否真的变好？（**相对基线**）
2. 状态表和知识图谱，哪个贡献更大？（**模块归因**）
3. 两者叠加是否优于单一模块？（**协同效应**）

---

## 二、实验设计：4 档消融

| 档位 | 名称 | 状态表注入 | 图谱注入 | 实现（环境变量） |
|---|---|:---:|:---:|---|
| `none` | 无记忆（基线） | ✗ | ✗ | `MEMORY_MODULES_ENABLED=false` |
| `state` | 仅状态表 | ✓ | ✗ | `MEMORY_KNOWLEDGE_GRAPH=false` |
| `graph` | 仅知识图谱 | ✗ | ✓ | `MEMORY_STATE_TABLE=false` |
| `both` | 状态表 + 图谱 | ✓ | ✓ | 全开（默认） |

**关键控制**：无论哪一档，图谱和状态表的**初始数据都先种好**，档位只控制「是否注入 Prompt」以及「是否增量更新」。这样四档的初始条件完全一致，差异只来自记忆模块本身，实验才干净。

---

## 三、数据与规模

**故事**：5 个，覆盖两类叙事结构（见 `tests/ab_ablation.ts` 的 `ALL_STORY_DEFS`）

| # | 故事 | 结构类型 | 角色数 | 关系复杂度 |
|---|---|---|---|---|
| 1 | 桃园结义 | 多角色多关系 | 4 | 结拜 + 敌对 |
| 2 | 张骞出使西域 | 单主线单角色 | 3 | 君臣 + 敌对 |
| 3 | 荆轲刺秦 | 单主线，强对抗 | 3 | 君臣 + 刺杀 |
| 4 | 赤壁之战 | 多角色多势力 | 4 | 同盟 + 敌对 |
| 5 | 郭子仪单骑退敌 | 三方博弈 | 3 | 旧交 + 敌对 + 同盟 |

**规模**：5 故事 × 4 档 × **5 段连续续写** = 100 条生成样本。

每个故事配一份预置的**状态表**（7–8 个对象）和**知识图谱**（5 条边），与故事设定对齐。

## 四、量化指标

| 指标 | 定义 | 方向 | 对应论文论点 |
|---|---|---|---|
| **Prompt 注入增量** | 相对 `none` 档的 Prompt 字符数增量 | — | 记忆确实进了生成链路（"从写到用"的证据） |
| **相邻段重复度** | 相邻段落的字符 trigram Jaccard 相似度均值 | 越低越好 | 情节不套路化 |
| **角色覆盖率** | 续写中至少被提及一次的角色占比 | 越高越好 | 不丢角色、不写飞 |
| **图谱增长** | 续写后图谱节点/边数增量 | 越高越好 | 图谱在生成过程中真实生长 |
| **状态表规模** | 分支下追踪的对象数 | 越高越好 | 状态追踪真实生效 |

> 说明：`角色覆盖率` 为本轮新增指标。旧版 `ab_compare.ts` 只有重复度，缺少"是否把角色写丢"这一维，而角色一致性恰是论文的核心卖点。

**后续可补的指标**（交给黄夏薇的 LLM-as-Judge 打分器）：
角色稳定 / 事件因果 / 时间线连续 / 情感连贯，四维 1–5 分。

## 五、运行方式

```bash
# 1. 起数据库
docker compose up -d postgres

# 2. 跑完整实验（5 故事 × 4 档 × 5 段）
DATABASE_URL=postgresql://gushi:gushi_dev@localhost:5433/gushi_dev \
  npx tsx tests/ab_ablation.ts --stories=5 --segments=5

# 3. 只跑指定档位 / 快速验证
npx tsx tests/ab_ablation.ts --arms=both,state --stories=1 --segments=1

# 4. 只重新生成报告（复用上次结果，不重跑 AI）
npx tsx tests/ab_ablation.ts --report-only
```

**产出**（落在 `Docs/ablation/`）：
- `ablation_results_<日期>.json` —— 原始数据，含全部生成文本，供打分器二次消费
- `ablation_report_<日期>.md` —— 量化表格 + 生成片段，可直接摘进论文

## 六、预期结论形态

论文「实验」章节需要落成这样的表格（跨故事平均）：

| 档位 | 相邻段重复度 ↓ | 角色覆盖率 ↑ |
|---|---|---|
| 无记忆（基线） | 待填 | 待填 |
| 仅状态表 | 待填 | 待填 |
| 仅知识图谱 | 待填 | 待填 |
| 状态表 + 图谱 | 待填 | 待填 |

**要论证的假设**：
- H1：`both` 的一致性指标优于 `none`（记忆注入有效）
- H2：`state` 与 `graph` 各有一项指标领先（两个模块互补而非冗余）
- H3：`both` 不劣于任一单模块（叠加无冲突）

## 七、方法学注意事项

1. **单次生成的随机性**：LLM 生成有随机性，单次结果不足以支撑结论。正式投稿前建议**每个配置重复 3 次取均值 ± 标准差**。
2. **样本量**：5 个故事是下限。若时间允许，扩到 10 个故事、每档 10 段，统计效力更好。
3. **人工校验**：量化指标只能反映"形式"，最终需配合人工阅读 + LLM-as-Judge 打分（黄夏薇负责），三者交叉印证。
4. **可复现性**：脚本固定了故事定义、初始状态表与图谱；seed 派生也已改为可复现（见 `src/lib/image-seed.ts` 的测试）。
