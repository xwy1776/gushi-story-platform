> 项目：古事（Gushi）· 多分支叙事的一致性维护
> 数据：`Docs/ablation/ablation_results_full_5x5.json` ｜ 报告：`Docs/ablation/ablation_report.md`
> 状态：**草稿**，数据为单轮 5 故事 × 4 档 × 5 段（n=5），投稿前需扩样

---

## 1. 实验设置

### 1.1 研究问题

本文提出「叙事状态表 + 知识图谱」的混合记忆注入，用于缓解长程故事续写中的前后文不一致。实验回答三个问题：

- **RQ1**：记忆注入能否降低续写内容的重复与套路化？
- **RQ2**：状态表与知识图谱两个模块各自贡献如何？
- **RQ3**：二者叠加是否优于单一模块？

> ⚠️ **RQ1 / RQ3 目前均无可用答案。** 首轮实验给出的肯定结论（"`state` 显著降低重复度"、
> "`both` 劣于 `state`"）在重跑后不成立，根因是所设计指标本身失效。
> 现状与修法见 §2.1 / §2.2 / §3.3-1，完整诊断见 [退化复读诊断.md](退化复读诊断.md)。

### 1.2 消融设计

四档消融，控制变量：所有档位的**初始记忆数据完全相同**，仅切换「是否将记忆注入 Prompt」与「是否增量更新记忆」。

| 档位 | 状态表注入 | 图谱注入 |
|---|:---:|:---:|
| `none`（基线） | ✗ | ✗ |
| `state` | ✓ | ✗ |
| `graph` | ✗ | ✓ |
| `both` | ✓ | ✓ |

### 1.3 数据

5 个故事，覆盖两类叙事结构：

- **多角色多关系**：桃园结义（4 角色）、赤壁之战（4 角色，多势力）
- **单主线/三方博弈**：张骞出使西域、荆轲刺秦、郭子仪单骑退敌

每档连续续写 **5 段**，共 **100 条**生成样本。基础模型 `deepseek-chat`，`max_tokens=700`，风格指令按题材自动生成。

### 1.4 指标

| 指标 | 定义 | 方向 |
|---|---|---|
| 退化复读率 | 相邻段落 trigram Jaccard 相似度 > 0.9 的相邻对占比（这些相邻对实测**逐字节相同**） | 越低越好 |
| 非退化中位数 | 剔除退化对之后，其余相邻对相似度的中位数 | 越低越好 |
| 相邻段重复度（均值） | 全部相邻对相似度均值。**双峰指标，被稀疏的退化复读事件支配，仅作观测量** | — |
| 角色覆盖率 | 续写中至少被提及一次的角色占比 | 越高越好 |
| Prompt 注入增量 | 相对 `none` 档的 Prompt 字符增量 | 观测量 |
| 记忆规模 | 图谱节点数 / 状态表对象数 | 观测量 |

> **为什么要把「重复度」拆开**：该指标的原始形态是双峰的——正常相邻对落在 0.01–0.15，
> 但模型偶尔会整段照抄上一段（相似度 1.00）。照抄会形成吸收态（照抄出的文本又成为
> 下一段的上文），单个触发点一次贡献 2 个以上 1.00，把该故事的均值从 ~0.05 抬到 ~0.5。
> 结果均值测的是"这次有没有抽到复读"而不是"该档记忆注入好不好"。
> 诊断过程与证据见 [退化复读诊断.md](退化复读诊断.md)。

## 2. 结果

### 2.1 主结果

跨 5 个故事的均值 ± 标准差。**同一份代码跑了两轮**（轮 1 / 轮 2）：

| 档位 | 退化复读率 ↓<br>轮1 / 轮2 | 非退化中位数 ↓<br>轮1 / 轮2 | 重复度均值<br>轮1 / 轮2 | 角色覆盖率 ↑ |
|------|------:|------:|------:|------:|
| `none`（基线） | 0.25 / 0.10 | 0.031 / 0.026 | 0.332 / 0.127 | 87% ± 18% |
| `state` | 0.00 / 0.15 | 0.034 / 0.035 | 0.043 / 0.233 | 80% ± 30% |
| `graph` | 0.20 / 0.30 | 0.030 / 0.031 | 0.254 / 0.324 | 87% ± 18% |
| `both` | 0.10 / 0.10 | 0.031 / 0.029 | 0.177 / 0.240 | **93% ± 15%** |

**结论：在当前样本量下，记忆注入对相邻段相似度没有可检出的影响。**

- **非退化中位数在两轮之间高度一致（0.026–0.035），且四档之间没有可见差异。**
  剔掉退化复读后，四个档位的正常段间相似度是同一个数。
- **重复度均值不可用**：`none` / `state` 两档根本不注入图谱，两轮的 Prompt 构造路径
  **完全一致**，但均值分别摆动 0.205 与 0.190；而轮 2 的档间最大差只有 0.11。
  **轮间差大于档间差**，说明该量在两轮之间测的是噪声。
- 唯一在四档上稳定的是**角色覆盖率**：`both` 档 93% 高于任一单模块（87% / 80%）。
  这是目前唯一在数据上站得住的模块互补证据，但仍需扩样确认。

### 2.2 关键观察：退化复读是模型侧的固有失效模式，与记忆注入无关

逐段分析发现一个在聚合均值中被掩盖的现象：**少数相邻段落相似度恰好为 1.00**。
检查原文——这些相邻对是**逐字节完全相同**的：

```
段3 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…
段4 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…
段5 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…
```

即模型整段照抄了上一段，而非"情节套路化"。它有两个放大机制：

1. **吸收态**：照抄出的文本又成为下一段的上文，模型会继续照抄。上例中段 3/4/5 全同，
   4 个相邻对里 2 个是 1.00，该故事均值从 ~0.05 抬到 0.512。
2. **n 太小**：n=5 时，一个故事触发就把该档均值抬高约 0.1，超过档间真实差异。

**已排除台架实现问题**：复读发生时，相邻两步的 Prompt 内容哈希与长度**都不同**
（2814 → 3098 字符），输出却逐字节相同；且同一 Prompt 连调三次输出互不相同
（采样确实是随机的）。发生率约 **5%/步**，且哪一轮触发是随机的。

**它与记忆档位无关**——按"该故事是否触发过复读"统计（两轮共 4 次机会）：
`荆轲刺秦` 4/4 触发（`none` 与 `graph` 两档、两轮都触发），
`郭子仪单骑退敌` 1/4，`赤壁之战` 1/4。
两轮之间**没有任何一段正文文本相同**，说明触发不是确定性的，
但「荆轲刺秦」这一故事的触发倾向明显更高——是**故事级**性质，不是档位级。

> 📌 **这一条修正了本稿早先的结论。** 早先基于轮 1 数据的"状态表抑制退化复读
> （`state` 档 5 个故事 0 次 1.00）"，在轮 2 里不成立：`state` 退化率 0.15，
> 反高于 `none`（0.10）。那是一次运气。相关的"图谱注入是负贡献"同样不成立。

**可转化为研究点**：退化复读是明确的生成质量缺陷，比"相邻段相似度"这种代理指标
更适合作为被解释变量。"记忆注入能否降低退化重复率"本身就是一个干净的可测假设。

### 2.3 统计检验

**本轮数据不支持任何档位间比较**，原因见 2.1：`none` / `state` 两档的 Prompt 代码路径
两轮完全未改动，均值却分别摆动 0.205 / 0.190，**轮间差大于档间差**；配对 t 检验
（df=4）在两轮里也都未达显著。因此不再列出基于均值的检验表——它会产生误导。

要得到可用结论，必须先扩样：**每档 ≥3 轮**，以 3 轮的非退化中位数取平均后再做配对检验。
现阶段可报告的只有：**四档在退化复读率与非退化中位数上均无可见差异。**


### 2.4 记忆系统的实际工作状态

| 档位 | 平均图谱节点 | 平均状态表对象 | Prompt 增量 |
|------|------:|------:|------:|
| `none` | 169.4 | 7.0 | — |
| `state` | 174.4 | **19.8** | +906 |
| `graph` | 200.0 | 6.6 | +1001 |
| `both` | 228.0 | 21.2 | +2337 |

- **状态表随续写持续生长**：`state`/`both` 档从 7 个对象增至约 20 个，证明增量更新在真实生成链路中生效
- **图谱持续扩张**：`both` 档平均达 228 节点（基线 169），说明关系抽取在持续工作
- **Prompt 代价**：`both` 档 Prompt 平均 5033 字，较基线增 87% —— 这是 2.1 中权衡的另一面，需在讨论中权衡"信息量 vs 上下文预算"

## 3. 讨论

### 3.1 模块互补性的意义

状态表回答"**现在是什么**"（符号化、精确匹配），图谱回答"**跟什么有关**"（关系结构、BFS 邻域）。

**但本实验尚未给出二者互补的证据**：如 §2.1 所述，重复度指标被退化复读事件支配，
四档在非退化中位数上没有可见差异；`state` / `graph` 的"分工"叙述来自轮 1 数据，
已被轮 2 推翻。唯一在两轮四档上方向一致的观测是**角色覆盖率**（`both` 93% > 任一单模块），
证据强度仍不足以下"混合记忆优于单一记忆"的结论，需要在扩样后重新检验。

> 📌 机制上的分工（符号化状态 vs 关系结构）仍然成立，且已有单元测试覆盖；
> 缺的是**生成质量层面**的支撑。这两件事要分开写。

### 3.2 本文相对 SCORE / DOME 的增量：分支感知

本文的关键差异点是 **分支感知（branch-aware）**：

- SCORE 的动态状态追踪与 DOME 的时序知识图谱均面向**单线叙事**，不存在"同一角色在不同分支处于不同状态"的场景
- 古事的多分支结构使该场景天然存在，本文的状态表与图谱均以 `branchId` 为隔离维度

> ⚠️ **当前实验并未验证这一点，这是本稿最大的论证缺口。**
>
> 上述 4 档消融的每个故事都只跑在**单一分支**（`branch_${tag}_${arm}`）上，本质是一个线性续写任务。
> 它验证的是「记忆注入是否有效」，**不是**「分支隔离是否有效」。
>
> 目前支撑分支感知的只有单元测试级证据：`tests/narrative-state-tracker.test.ts`
> （同一角色在两分支状态不同、写 B 分支不污染 A 分支）与 `tests/knowledge-graph.test.ts`
> （同名节点在不同分支是不同节点）。**单元测试能证明机制正确，但不能证明它改善了生成质量。**
>
> 审稿人几乎必然会问："你声称分支感知是核心创新，那么分支感知的实验在哪里？"
> 因此本节必须在补做「跨分支污染」实验（设计见 §4-1）之后，才能作为论文主线成立。

### 3.3 局限

1. **指标有效性**（本轮新发现，最主要）：所设计的「相邻段重复度均值」是双峰指标，
   被稀疏的退化复读事件（约 5%/步）支配——`none` / `state` 两档 Prompt 代码路径两轮
   完全未改，均值却分别摆动 0.205 / 0.190，**轮间差大于档间差**。
   详见 [退化复读诊断.md](退化复读诊断.md)。修法是拆分指标（§1.4），但需要重新跑数。
2. **样本量不足**：5 故事 × 1 轮，统计检验均不显著；扩到每档 ≥3 轮才有统计效力
3. **单一基础模型**：仅 `deepseek-chat`，结论的模型泛化性未知
4. **指标偏形式化**：trigram 重复度只能反映表层重复，无法衡量"情节因果是否连贯""人物性格是否漂移"——需引入 LLM-as-Judge 多维打分（角色稳定/事件因果/时间线连续/情感连贯）作为补充
5. **未接入人工评估**：需人工阅读打分与自动指标交叉印证

## 4. 下一步

### 4-0【新增·最高优先级】扩样重跑

单轮数据已证明不可用（§2.1 / §3.3-1）。必须先做：

| 项 | 设计 |
|---|---|
| 规模 | 5 故事 × 4 档 × 5 段 × **3 轮**（约 300 次生成，注意 `AIRequestQueue` 20 次/分钟限流） |
| 报告 | 每档报「退化复读率」与「非退化中位数」的 3 轮均值；均值仅作观测量 |
| 检验 | 以故事为单位配对，对**非退化中位数**做配对 t 检验 |
| 附加 | 把「记忆注入能否降低退化复读率」作为一个**独立假设**检验——它是明确的生成缺陷，比相似度代理指标更干净 |
| 顺带 | 查清为什么「荆轲刺秦」的触发倾向明显更高（4/4），是否与起始片段已写到"荆轲已死"、续写缺乏可推进目标有关 |

> 复跑命令：`npx tsx tests/ab_ablation.ts --stories=5 --segments=5`（重复 3 次）

### 4-1【最高优先级】补做「跨分支污染」实验 —— 让主线成立

这是把「分支感知」从**机制正确**提升到**效果可证**的唯一途径，也是本文能否成立的关键。

**设计草案**：

| 项 | 设计 |
|---|---|
| 场景 | 同一故事的同一分叉点，造出两条**设定冲突**的分支：<br>A 分支：刘备与曹操结盟；B 分支：刘备与曹操反目 |
| 续写 | 在 **A 分支**继续续写 5 段（B 分支的事件绝不应出现） |
| 对照 | 2 档 × 2 组：<br>① 分支隔离**开**（现状，状态表/图谱按 `branchId` 隔离）<br>② 分支隔离**关**（人为让检索忽略 `branchId`，模拟 SCORE/DOME 的单线记忆） |
| 指标 | **跨分支污染率**：A 分支续写中引用了 B 分支专属事件/状态的段落占比（由 LLM-as-Judge 或关键词匹配判定）<br>**反向亦然**（B 分支不得引用 A 分支） |
| 预期 | 隔离开启时污染率显著低于关闭时；这正是 SCORE/DOME 结构上做不到的事 |

**样本**：≥5 个故事的冲突分支对 × 2 档 × 5 段 = 100 条，与主实验同量级。

**为什么这是必须补的**：主实验（4 档消融）证明的是"记忆有用"，
SCORE / DOME 也能证明；只有这个实验能证明"**分支隔离**有用"，而那是本文独有的贡献。
