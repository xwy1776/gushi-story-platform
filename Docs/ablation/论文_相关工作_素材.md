## 一、这一节要立什么

评测这一支的相关工作，需要立住三件事：

1. **LLM-as-Judge 已是通行做法，但它的「效度」本身就是一个被研究的问题** ——
   不是「用了 Judge 就行」，而是要回答「Judge 测的是不是我们想测的东西」。
2. **叙事与长文本评测长期以人工为事实标准；而「评测指标本身」也有专门的基准** ——
   OpenMEVA 评的就是指标，不是模型。
3. **既有工作（SCORE / DOME 等）都是单线叙事**，评测体系里没有「跨分支一致性」这一维 ——
   这正是本文的评测增量所在。

## 二、路线一：LLM-as-Judge 及其效度

### 2.1 奠基：Judge 与人类偏好的对齐

**Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena**（Zheng et al., 2023）｜ arXiv:2306.05685

- **一句话**：系统研究「用强模型当裁判」的可行性、偏差与缓解方法，并用 MT-Bench 与 Chatbot Arena 验证 Judge 与人类偏好的一致性。
- **三类偏差**（论文明确列出）：
  - **位置偏差**（position bias）：倾向偏好靠前的答案
  - **冗长偏差**（verbosity bias）：倾向偏好更长的答案
  - **自我增强偏差**（self-enhancement bias）：倾向偏好与自己风格相近的答案
- **与本文的关系**：
  - 本文**不做成对比较**，而是对每条文本**独立判定** —— 这天然规避了位置偏差。
  - 本文沿用该文的 **Cohen's κ** 口径衡量 Judge 与人类的一致性。
  - ⚠️ **可写的差异**：该文报告的是「Judge 与人类偏好的一个总体一致率」；
    本文进一步区分**逐段一致率**（κ=0.47，中等）与**聚合结论的吻合度**
    （人工口径 57.4% vs Judge 55.0%），并解释两者为何可以并存。

### 2.2 构念效度：Judge 到底在测什么

**Measuring what Matters: Construct Validity in LLM Benchmarks**（2025.11）｜ arXiv:2511.04703

- **一句话**：29 位专家系统审查 **445 个 LLM benchmark**，发现大量「测的现象、任务与评分指标」之间存在**构念错位**，并给出 8 条可操作建议。
- **核心概念**：**构念效度（construct validity）** —— 测量工具是否真的在测它声称要测的抽象构念。
- **与本文的关系**（★★★ 最重要的一篇）：
  - 本文用「**单图与规范的接近度**」来论证「**跨图一致性**」，正是一个**构念错位**的典型：
    「两张图看起来像」不等于「两张图画的是同一个角色/同一段情节」。
  - 这篇给了我们**批评自己指标**的理论语言，也让「人工锚定 + 多指标对照」有了方法论依据。
  - **可直接写进论文的论点**：
    > 自动指标的有效性不能靠「看起来合理」来辩护，必须显式论证其构念效度；
    > 本文用人工锚定、双度量分歧分析与失效模式记录来回应这一要求。

### 2.3 多维、标准化、全原始输出公开

**Holistic Evaluation of Language Models（HELM）**（2022.11）｜ arXiv:2211.09110

- **一句话**：对语言模型做**多场景 × 多指标**的整体评测，并强调标准化与透明。
- **三条骨架**（与本文直接对应）：
  1. **多维度**：不只看 accuracy，而是 7 个指标（accuracy / calibration / robustness / fairness / bias / toxicity / efficiency）
  2. **标准化**：统一的场景分类与指标定义，使不同模型可比
  3. **全原始输出公开**：所有 prompt 与模型输出可复现、可审计
- **与本文的关系**：
  - 本文的「四维打分 + 双度量 + 人工锚定」在结构上对应 HELM 的**多指标**原则。
  - 本文把所有 prompt、采样原始分、逐条判定都落盘，对应**透明与可复现**原则。
  - ⚠️ 差异：HELM 是通用模型评测；本文是**领域特定（叙事一致性）**的评测，指标更细但覆盖面更窄。

### 2.4 把主观评价转成可复现判定

**τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains**（2024.06）｜ arXiv:2406.12045

- **一句话**：用「**预定义规则 + 数据库终态比对**」判定 agent 是否完成任务，把主观评价转成**可复现的客观判定**；并提出 **pass^k** 衡量多次试验的可靠性。
- **关键做法**：
  - 对话结束后，把**数据库状态**与**标注的目标状态**比对，而不是让 Judge 主观打分
  - **pass^k**：同一任务跑 k 次，要求 k 次都成功 —— 衡量**一致性**而非单次能力
- **与本文的关系**（★★）：
  - 本文的跨分支污染判定其实是一个**可规则化**的任务：主角是否进入乙分支的地点/事件。
    这正是 τ-bench 式「预定义规则判定」的思路。
  - **pass^k 的启示**：本文目前是「每条采样 3 次取中位数」，衡量的是**度量稳定性**；
    τ-bench 衡量的是**模型行为稳定性**。两者可以并列写，但不要混为一谈。
  - 可借鉴：**把判定规则写死、把原始输出全公开**，降低对 Judge 主观性的依赖。

## 三、路线二：叙事与长文本评测

### 3.1 评测「指标本身」的基准

**OpenMEVA: A Benchmark for Evaluating Open-ended Story Generation Metrics**（2021.05）｜ arXiv:2105.08920

- **一句话**：**不是评模型，而是评指标** —— 系统检验自动指标与人类判断的相关性、泛化性、连贯性判断能力与鲁棒性。
- **四个测试维度**：
  - (a) 与人类判断的**相关性**
  - (b) 对不同模型输出与数据集的**泛化性**
  - (c) 判断**故事连贯性**的能力
  - (d) 对扰动的**鲁棒性**
- **核心发现**：现有自动指标与人类判断**相关性很差**，也无法可靠判断连贯性。
- **与本文的关系**（★★★）：
  - **同源思路**：OpenMEVA 评「指标」，本文用人工锚定评「Judge」——都是在问「这个度量本身可信吗」。
  - 本文可以直接引用它的结论作为**动机**：自动指标与人类判断的弱相关，是引入人工锚定的理由。
  - 差异：OpenMEVA 面向**开放式故事生成**的通用指标；本文面向**多分支叙事**的**跨分支一致性**这一特定构念。

### 3.2 长文本生成的系统评测

**HelloBench: Evaluating Long Text Generation Capabilities of LLMs**（2024.09）｜ arXiv:2409.16191

- **一句话**：基于 Bloom 分类学把长文本生成拆成 **5 类子任务**（开放问答、摘要、对话、文本补全、启发式文本生成），并提出 **HelloEval** 这一与人类对齐的评测方法。
- **与本文的关系**：
  - 「启发式文本生成」一类与故事续写最接近，可作为**任务分类**的参照。
  - HelloEval 的「与人类对齐」思路，与本文的人工锚定同向。
  - 差异：HelloBench 评的是**长度与任务完成**；本文评的是**跨分支事实一致性**，不关心长度。

### 3.3 连续故事可视化（图文一致性）

**StoryBench: A Multifaceted Benchmark for Continuous Story Visualization**（2023.08）｜ arXiv:2308.11606

- **一句话**：面向**文生视频**的连续故事可视化基准，要求视频在帧间**保持一致性**，并设计了三个递进任务（动作执行、故事续写等）。
- **与本文的关系**（⚠️ 注意）：
  - 它评的是**跨帧视觉一致性**，与本文的「跨分支文本一致性」是**不同模态的同构问题**：
    都在问「后续生成是否与前面的设定保持一致」。
  - 可用于**类比论证**：一致性问题不是文本独有的，跨模态同样存在。
  - **不要**把它写成「文本故事评测」——它是 **text-to-video**，引用时必须说准。

### 3.4 超长输出与分解式生成

**LongWriter: Unleashing 10,000+ Word Generation from Long Context LLMs**（2024.08）｜ arXiv:2408.07055

- **一句话**：发现模型的**有效生成长度受 SFT 样本长度限制**，提出 **AgentWrite** 把超长生成拆成子任务，并用 LongWriter-6k 数据训练。
- **与本文的关系**：
  - 与「长程/长文本」相关，但关注的是**输出长度**，不是**跨分支一致性**。
  - 可作为「长文本生成」背景引用，**不作为核心对标**。

### 3.5 叙事一致性的维度来源（已有素材）

**SCORE: Story Coherence and Retrieval Enhancement for AI Narratives**（2025.03）｜ arXiv:2503.23512

- 定义 **NCI-2.0** 叙事一致性指标：**角色稳定 / 事件因果 / 时间线连续 / 情感连贯**。
- ⚠️ 本文四维评分器的四个维度**直接沿用该体系** —— 成文时必须引用并说明沿用，不能写成自创。

**DOME: Dynamic Hierarchical Outlining with Memory-Enhancement**（2024.12）｜ arXiv:2412.13575

- 用时序知识图谱 + 动态大纲，报「冲突减少 87.6%」。
- **与本文的关系**：DOME 是**单线**叙事；本文的多分支场景下「同一角色在不同分支状态不同」，
  其评测体系里没有对应维度 —— 这是本文评测部分的增量位置。

## 四、我们与它们的差异（可写成 contribution）

| # | 本文做法 | 相对既有的差异 | 支撑材料 |
|---|---|---|---|
| 1 | **跨分支一致性**作为独立评测维度 | SCORE / DOME 均为单线叙事 | 实验 B |
| 2 | **对同一现象并行报告两个自动指标**，并公开分歧 | 既有工作多只报一个指标 | 关键词法 vs Judge 一致率 70% / 82% |
| 3 | **为自动判定做人工锚定**，且区分逐段与聚合两个层次 | 既有工作多只报一个人工一致率 | 人工评估报告 |
| 4 | **记录度量工具本身的不稳定性** | 鲜有工作记录此类 API 层事实 | `评测方法说明.md` §四 |
| 5 | **用构念效度语言检视自己的指标** | OpenMEVA 评指标，但未针对多分支叙事 | 本文件 §2.2 |

> 📌 第 4 条是成本最低、可读性最高的一条：不依赖任何实验结论，只是把踩过的坑写清楚。

## 六、待补与注意

1. **SCORE / DOME 的引用信息**已在 `Docs/paper_summaries_0816.md`，成文时统一格式。
2. **StoryBench 是 text-to-video**，引用时不能写成文本评测。
3. 「相关工作」成文时，建议按**两条线**组织：
   - 评测方法线：LLM-as-Judge → 构念效度 → 多指标标准化 → 规则化判定
   - 叙事评测线：开放式故事指标 → 长文本生成 → 连续可视化 → 单线叙事的记忆评测
4. 本文的定位句（草稿）：
   > 现有评测要么只测单线叙事的一致性，要么只检验通用指标与人类的相关性；
   > **缺少针对多分支叙事、且经过人工锚定的评测协议**。本文补的是这一块。
