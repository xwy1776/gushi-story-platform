# LLM-as-Judge 一致性评测方法说明

> 撰写：黄夏薇 ｜ 更新：2026-09-17
> 分支：`xiawei/llm-judge` ｜ 对应代码：`tests/llm_judge.ts`、`tests/make_charts.ts`
> 用途：论文「评测方法」章节素材 + 组内复现依据

---

## 一、要评什么

方法侧的消融实验（见 [进度与交接.md](进度与交接.md)）原本依赖词汇级指标
「相邻段重复度均值」，但 4 轮数据表明该指标**被稀疏的退化复读事件支配，
轮间差大于档间差**——即指标失效。

本评测提供**语义层面**的一致性度量，作为词汇级指标的补充：

| 对比 | 词汇级指标 | 本评测 |
|---|---|---|
| 度量对象 | 字面重复（trigram 相似度） | 叙事连贯性（四维语义） |
| 能否发现「复读」 | 能 | 能（表现为「时间线倒错」） |
| 能否区分「重复但合理」与「重复且破坏叙事」 | **不能** | 能 |
| 粒度 | 段间 | 篇级（一条续写 = 5 段合并评价） |

> ⚠️ 一个必须写进论文限制章节的观察：**「时间线连续」这一维会被退化复读污染**
> （复读被 Judge 记为「时间线原地倒错」）。也就是说四维之中有一维与词汇级指标
> 在测同一现象，二者并非完全正交。

---

## 二、四个维度与评分锚点

四维各 1–5 分，**各自独立套用同一套锚点**。

| 维度 | 英文键 | 定义（喂给 Judge 的原话） |
|---|---|---|
| **角色稳定** | `character` | 角色的身份、性格、说话方式、能力是否与角色设定和前文一致。出现 OOC（性格偏离）、已登场角色凭空消失、或冒出未交代来路的新角色，都要扣分。 |
| **事件因果** | `causality` | 事件之间是否有清晰的因果链，人物行为的动机是否成立。无铺垫的突兀转折、行为缺乏动机、情节靠巧合硬推，都要扣分。 |
| **时间线连续** | `timeline` | 时间推进是否连贯有序，与故事梗概/前文交代的时间、季节、地点是否矛盾，有无倒错、跳跃失据。 |
| **情感连贯** | `emotion` | 情感基调是否连贯、有合理的过渡与层次。情绪突变、情感扁平、在特定情境下出现不匹配的情绪，都要扣分。 |

**评分锚点**

| 分 | 含义 |
|---|---|
| 5 | 优秀：该维度全程无瑕，处理得当，无一处可指摘 |
| 4 | 良好：整体不错，仅有个别轻微不足，不影响阅读 |
| 3 | 及格：有明显问题，但不算严重，整体仍可读 |
| 2 | 较差：该维度多处出错，已明显影响阅读体验 |
| 1 | 很差：该维度严重违反，破坏文本的基本可信度 |

**总分** = 四维之和，范围 4–20。论文中报告「四维分 + 总分」，不报告加权总分——
权重没有依据，且会掩盖维度间的分歧模式。

### 打分纪律（写进 system prompt 的约束）

- 严格基于文本证据，不因题材著名、文笔华丽而放宽连贯性标准
- 明确区分**连贯性**与**文采**：不因「写得美」抬高分数
- 某维度确实无法评估时给 3 分并说明原因，而不是跳过
- 每条理由必须具体、指向文本证据，≤40 字
- 不机械回避 1 分和 5 分

## 三、打分流程

```
消融实验输出（ablation_results_*.json，含 story / arm / segments）
        │
        ▼
  ① 组装上下文 ── 故事梗概 + 角色性格基准 + 起始段（前文）+ 待评续写
        │
        ▼
  ② 调 Judge ── temperature=0、response_format=json_object，每条采样 N 次
        │
        ▼
  ③ 聚合 ── 每维取 N 次采样的**中位数**，理由取最接近中位数那次的原话
        │
        ▼
  ④ 统计 ── 档位均值、跨轮汇总、相对基线的**配对**差值与 95% CI
        │
        ▼
  ⑤ 出图 ── make_charts.ts → judge_charts.html（3 图 + 2 表）
```

### 上下文为什么要带角色设定

判断「角色稳定」需要一个基准，否则 Judge 只能靠先验知识猜。因此把每个故事的
`characters[].traits` 一并喂进去（fixture 见 `tests/story-fixtures.ts`）：

```
【角色设定】（判断「角色稳定」的基准）
- 刘备（主角）：仁义、沉稳、坚韧
- 关羽（主角）：忠义、勇猛、高傲
- 张飞（配角）：勇猛、急躁、忠诚
```

起始段（`opener`）作为「前文」提供，使时间线判断有参照。

### 为什么不用项目里的 `callAIText()`

`src/lib/ai-client.ts` 的 `buildOpenAIRequest()` 把 temperature 写死成按题材算出的
0.4 / 0.5 / 0.6，**调用方没有任何覆盖入口**。而打分器要求可复现，必须能压到 0。
故评测器自建了一个最小 fetch 封装，只复用 `extractJsonFromAI()` 这个纯函数。

### 统计口径

- **配对（paired）而非独立**：同一轮次、同一故事下比较处理档与基线，
  控制掉故事间差异。这是本评测与消融实验的主要统计改进。
- **多重比较必须校正**。一次分析里做了 3 个比较（`state`/`graph`/`both` 各与基线比），
  故用 **Bonferroni 校正**：α = 0.05/3 ≈ 0.0167，df=24 下临界 t = **2.574**
  （未校正时是 2.064）。不校正会抬高族错误率——比较越多，
  越容易有一个「碰巧显著」，这正是本项目踩到的坑（见 §五）。
- **报告真实 p 值**，而不是只给「显著/不显著」的星号，便于读者自行按其他口径判读。
- 样本量偏小，**该判据仅作粗筛**，不宣称严格显著性。

t 分布的双尾 p 值由 `tests/paired-stats.ts` 自行实现（Lanczos 近似 + 不完全贝塔连分数），
未引入统计库；实现已用 t=2.064→p=0.0500、t=2.797→p=0.0100 等标准值校验。

## 四、可复现性

### 实测数据（桃园结义 4 档 × 每条 10 次独立采样，temperature=0）

| 指标 | 数值 |
|---|---|
| 10 次采样**完全一致**的（条目×维度）比例 | **13/16 = 81%** |
| 全部 16 个（条目×维度）的平均标准差 | **0.079**（1–5 量表） |
| 有分歧的 3 个 | 均为「主分 + 偶发 ±1」（如 2 分×7、3 分×3） |
| 全量 100 条 × 3 次采样（300 次调用）的最大极差 | **1 分**（无更大） |

**结论**：`temperature=0` 下打分高度可复现；残余噪声是 ±1 的偶发偏移，
**中位数聚合可完全吸收**。故默认 `--repeats=3`。

### ⚠️ 两个必须记录的工程事实

**① temperature=0 不保证确定性。** 相同输入、相同参数，DeepSeek 仍会偶发
返回不同分数（约 19% 的条目×维度出现 ±1 漂移）。因此「多次采样取中位数」是
**必需步骤**，不是可选优化——这条应写进论文的评测协议。

**② DeepSeek 的 `response_format: json_object` 会概率性丢掉结尾的 `}`。**
实测命中率约 37%（3/8），且此时 `finish_reason` 仍报 `stop`、
`completion_tokens` 也正常，**调用方无法从响应元数据察觉**。

这个 bug 的危害不止于解析失败：`extractJsonFromAI()` 的平衡括号匹配会退而
匹配到**内层**的 `{"score":..,"reason":..}` 并成功返回，于是拿到一个缺
`character` 等键的对象——失败会伪装成成功。

应对：`repairTruncatedJson()` 按括号栈补齐缺失闭合符（跳过字符串内部与转义符），
修复后**解析失败率 25% → 0**。该补丁对截断与真·非法 JSON 都安全，
因为它在原样解析成功时不会被触发。

> 任何用 LLM 做结构化输出评测的工作都应记录此类 API 层不稳定性——
> 它直接影响数据完整性，且不体现在 API 的错误返回里。

## 五、结果

数据：`ablation_results_*.json` 共 5 个文件（4 轮 + 1 次 full_5x5），
**100 条**（5 故事 × 4 档 × 5 轮），每条 3 次采样，共 300 次 Judge 调用。

### 各档四维均分（全部轮次合并，n=25/档）

| 档位 | 角色稳定 | 事件因果 | 时间线连续 | 情感连贯 | 总分均值 |
|---|---|---|---|---|---|
| `none`（无记忆） | 3.44 | 2.60 | 2.04 | 2.76 | **10.84** |
| `state`（仅状态表） | 3.60 | 2.80 | 2.64 | 3.28 | **12.32** |
| `graph`（仅图谱） | 3.68 | 2.76 | 2.52 | 3.04 | **12.00** |
| `both`（状态表+图谱） | 3.44 | 2.76 | 2.52 | 3.12 | **11.84** |

### 配对分析（同一轮次+同一故事，处理档 − 基线）

Bonferroni 校正后 α = 0.0167，**临界 t = 2.574**（df=24）。

| 对比 | n | 差值均值 | 校正区间 | 未校正 95% CI | t | p 值 | 未校正 | **校正后** |
|---|---|---|---|---|---|---|---|---|
| `state − none` | 25 | +1.48 | ±1.75 | ±1.33 | 2.18 | 0.0392 | ~~显著~~ | **不显著** |
| `graph − none` | 25 | +1.16 | ±1.68 | ±1.28 | 1.78 | 0.0881 | 不显著 | 不显著 |
| `both − none` | 25 | +1.00 | ±1.63 | ±1.24 | 1.58 | 0.1269 | 不显著 | 不显著 |

> ⚠️ `state` 的 p=0.0392 **小于 0.05 但大于校正后的 0.0167**。
> 只看未校正的 α=0.05，会把它误报为「显著」——本报告早期版本就犯过这个错。
>
> ⚠️ 绘图与报告一律使用**校正区间**（±1.75 等，由临界 t=2.574 算出），
> 不是常见的 95% CI。两者不可混用：用未校正的 95% CI 配校正后的显著性判定，
> 图上会出现「误差棒不跨 0 却标注不显著」的自相矛盾。

### 各轮内部排序（总分均值从高到低）

```
R1  ： none(11.8) > state(11.8) > graph(11.4) > both(11.4)   ← none 竟排第一
R2  ： graph(13.0) > both(12.8) > state(12.4) > none(10.8)
R3  ： graph(12.0) > state(11.6) > none(11.2) > both(11.2)
R4  ： state(12.8) > graph(12.8) > both(12.2) > none(10.0)
full： state(13.0) > both(11.6) > graph(10.8) > none(10.4)
```

### 结论（三条，按可信度排序）

**① 记忆注入相对无记忆有一致的正向趋势。** 三个处理档在总分上均高于基线，
且方向与消融实验的「退化复读率」一致（`none` 最差）。这是本评测**能支持**的结论。

**② 三个处理档之间无法区分。** 经 Bonferroni 校正后（α=0.0167），
三个比较**无一显著**（p 分别为 0.039 / 0.088 / 0.127）。`state` 的未校正
p=0.039 看似显著，但校正后不成立——这正是多重比较校正的意义所在。
此外 `state` 的优势来自少数大差值而非普遍更好：`both` 有 15/25 条优于基线
（比 `state` 的 13 条更多），只是差值均值更小。**不能据此宣称任一处理档最优。**

**③ 档位排序在各轮之间漂移。** R1 中 `none` 排第一，而它在其余四轮均垫底。
这说明**档间差异小于轮间波动**——与词汇级指标遇到的困境同源。

> 📌 因此，论文中**不应**写「加入状态表+图谱后一致性提升」这类排序性结论。
> 可写的是「记忆注入相对无记忆呈一致正向趋势，但现有样本量不足以区分各注入
> 组合的优劣」。这也正是交接文档里「扩故事数到 12–15」的动因——差的是故事数，
> 不是轮数。

## 六、复现步骤

```bash
# 0) 起数据库（评测本身不连库，但消融数据由实验脚本产出）
docker compose up -d postgres

# 1) 批量打分（100 条 × 3 次采样 ≈ 100 秒）
npx tsx tests/llm_judge.ts --all --repeats=3

# 2) 出图表
npx tsx tests/make_charts.ts

# 3) 只重出报告、不重跑 API（改报告格式或统计口径时用）
npx tsx tests/llm_judge.ts --report-only

# 输出
#   Docs/ablation/judge_results_<时间戳>.json   结构化结果（含每次采样原始分）
#   Docs/ablation/judge_report_<时间戳>.md      文字报告
#   Docs/ablation/judge_charts.html             图表（自包含，浏览器打开）
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--all` | 扫 `Docs/ablation/ablation_results_*.json` 全部文件并分轮次 |
| `--input=<path>` | 只评单个文件 |
| `--stories=桃园结义,张骞出使西域` | 按故事过滤 |
| `--arms=both,none` | 按档位过滤 |
| `--repeats=N` | 每条采样次数（默认 3；**测稳定性用 10**） |
| `--limit=N` | 只评前 N 条 |
| `--dry-run` | 只打印 prompt，不调 API（调试省钱） |
| `--check-fixtures` | 校验 `story-fixtures.ts` 与 `ab_ablation.ts` 的一致性 |

## 七、已知限制

1. **样本量不足**：每档 25 条（5 故事 × 5 轮），不足以支撑档间比较。
2. **「时间线连续」维度被退化复读污染**（见 §一），四维并非完全正交。
3. **单一 Judge 模型**：全部结果来自 `deepseek-chat`（后端路由到 `deepseek-flash`）。
   未做多模型交叉验证，存在模型自偏好风险。
4. **无人工标注锚定**：评分绝对水平未与人类评分对齐，本评测的结论应只在
   **档位间相对比较**的意义上使用，绝对分数不宜直接引用。
5. **同一 Judge 打所有档位**：虽然对每条文本独立评分（非成对比较），
   但 Judge 未对档位标签知情——这一点是刻意设计的，避免标签泄露偏见。
