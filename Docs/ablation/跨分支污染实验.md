# 跨分支污染实验：「分支感知」到底有没有用

> 2026-09-15 ｜ 脚本 [`tests/ab_branch_isolation.ts`](../../tests/ab_branch_isolation.ts)
> 主结果报告 `v2_rounds_report.md` ｜ 原始数据 `branch_isolation_n12_v2_*.json`
>
> **结论：分支隔离把跨分支事实泄漏从 50% 压到 19%（净 31 个百分点，
> 配对 t = 2.97，df = 11，p < 0.05），逐故事 10 胜 0 平 2 负。**
> 但效应依赖于分叉设计 —— 详见 §五（该节按设计迭代顺序写，
> v1 只有 12pp 且不显著，改设计后才有 31pp）。

---

## 一、为什么必须做这个实验

4 档消融（`ab_ablation.ts`，见 [论文_实验与结果_草稿.md](论文_实验与结果_草稿.md)）证明的是
**「记忆注入有用」**。但 SCORE(2025.03) 和 DOME(2024.12) 也是记忆系统，**它们同样能证明这件事**。

本文相对它们的唯一增量是**分支感知（branch-aware）**：同一角色在不同分支处于不同状态时，
记忆按 `branchId` 隔离。而那个消融的每个故事**只跑单一分支**，本质是线性续写任务 ——
**它在结构上就测不到分支感知**。

在跑这个实验之前，支撑"分支感知"的只有单元测试级证据（同一角色在两分支状态不同、
写 B 分支不污染 A 分支）。单元测试能证明**机制正确**，证明不了**效果**。

> 审稿人几乎必然会问："你声称分支感知是核心创新，那么分支感知的实验在哪里？"
> 这个实验就是那个答案。**它决定论文的主线能不能成立**——如果隔离开/关两档没有差异，
> 论文就失去了唯一的增量贡献。这与"扩样本量"那种降低风险的实验性质不同。

## 二、设计

### 2.1 场景

对 5 个故事各造一个分叉点，两条**设定互斥**的分支甲 / 乙。例如桃园结义：

| | 设定 | 记忆里的事实 |
|---|---|---|
| **分支甲** | 投公孙瓒，借兵讨董 | 刘备驻**北平**，盟友公孙瓒，借兵三千 |
| **分支乙** | 投曹操，会盟讨董 | 刘备驻**许都**，盟友曹操，会盟讨董 |

**只在分支甲上续写 5 段。**

### 2.2 两档对照

| 档位 | 做法 | 对应现实中的系统 |
|---|---|---|
| `isolated` | 甲的事实挂 `branchId=甲`，乙的事实挂 `branchId=乙` → 甲的检索看不见乙 | **本文做法** |
| `shared` | 甲、乙的事实**都**挂到甲的检索空间 | **SCORE / DOME 式单线记忆**（一个故事只有一份记忆，没有分支维度） |

`shared` 档刻意**不去改库代码**：把乙的事实也塞进甲的检索空间，正是"没有分支维度"的
系统自然会发生的事——它的记忆池里同时躺着两套互斥设定。

### 2.3 指标与主估计量

**跨分支污染率** = 甲分支续写段落中，采用了乙分支独有事件/状态的段落占比。

> ⚠️ **不要直接比较两个绝对污染率。** 隔离开着也会测出非零污染，因为模型的**世界知识**
> 本身就会产出与乙相似的桥段（三国题材里"刘备与曹操会盟"是史实，不靠注入也会写）。
> 那是先验，不是泄漏。

**主估计量 = 单线档污染率 − 隔离档污染率**（净泄漏增量）。隔离档在这里的作用是
**扣掉模型先验的对照**，不是"应该等于 0 的期望值"。

用两个**互相独立**的度量，并报告一致率：

| 度量 | 做法 | 性质 |
|---|---|---|
| 关键词法 | 段落是否命中乙分支的专属措辞 | 客观、可复算、便宜，但**粗**（见 §四） |
| LLM-as-Judge | 把甲/乙设定 + 正文给模型判定 | 能处理语义与改写，**主判定** |

之所以要两个：本项目已经吃过一次「指标静默失效」的亏（见 [退化复读诊断.md](退化复读诊断.md)），
单一指标的结论不可信。

## 三、⚠️ 试跑揪出的四个设计缺陷

这一节是本文档最有价值的部分。**四个缺陷都是在正式跑之前、用小样本试跑发现的**，
而且每一个都足以让结论完全反转。记下来是因为它们都是"看起来合理但实际在测别的东西"的典型。

### 缺陷 ①：分叉点 opener 把两个选项都写出来了

最初的分叉点片段写成：

> "…摆在三人面前的有两条路：**是北上投奔公孙瓒借兵，还是东行投奔曹操会盟**？刘备沉吟良久…"

**两档共见这段 opener**，于是乙分支的地名（许都）和人名（曹操）从一开始就在上下文里，
模型自然照写。结果 `isolated` 档测出 50% 污染率 —— **那是 opener 泄漏，不是记忆泄漏**。

**改法**：opener 停在分叉点上，**刻意不写任何一条分支的去向**。分支必须**只由注入的记忆决定**。

```diff
- …摆在三人面前的有两条路：是北上投奔公孙瓒借兵，还是东行投奔曹操会盟？刘备沉吟良久，终于做出决断。
+ …欲讨董卓，必先得一强援。刘备在中军帐中展开舆图，久久不语——投奔何人、屯驻何地，这一步走错，三人便再无翻身之日。
```

改完后 `isolated` 档从 50% 降到 0~33%（剩下的部分是模型先验，见 §2.3）。

### 缺陷 ②：拿著名历史人物当标记词

最初把「曹操」列为分支乙的标记词。但**曹操在三国题材里是常识**，模型凭空写出来
不代表记忆泄漏。实测 `isolated` 档第 2 段编了个曹操客串（"原来曹操自陈留起兵…特来相会"），
关键词法立刻判污染 —— **假阳性**。

**改法**：标记词**只用地点/事件专有名词**（北平、许都、督亢、辽东…），不用人物名。
并把这条规则写进代码注释，防止后人改回去。

### 缺陷 ③：标记词是通用词

一度把「会盟」「退守」「娶妻」「固守」当标记词。这些都是**通用叙述词**：
"诸侯会盟讨董"是三国故事的背景常识，模型写它跟分支无关。实测 `isolated` 档
三段全部命中「会盟」，Judge 全判干净 —— **关键词法 100% 假阳性**。

**改法**：同 ② —— 专有名词优先。这条经验与 ② 合并成"挑词两条规则"写进了代码。

### 缺陷 ④：LLM-as-Judge 的采样温度没锁

Judge 最初走默认的题材温度推断，拿到 **0.5**。同一段文本两次判定可能给出相反结论 ——
**度量工具本身是随机的**，这对主指标是致命的。

**改法**：给 `callAIText` / `callAI` / `buildOpenAIRequest` 加了 `temperature` 覆盖参数
（默认行为不变），判定调用显式传 `0`。

```ts
const raw = await callAIText(prompt, { maxTokens: 300, temperature: 0 });
```

### 附：两个台架 bug

- **段 id / 分支 id 是模块级常量**（`seg_fork_main_000`、`branch_fork_A`），
  所有故事共用 → 第二个故事 setup 时撞 Prisma 唯一键直接崩（P2002）。
  改成一律带故事名。**同一个坑踩了两次**（段 id 修完，分支 id 又犯），
  第二处修完顺手给每个"故事×档位"加了 try/catch，避免单点失败拖垮整轮。
- 试跑脚本用 `| head -N` 截断输出，管道关闭触发 SIGPIPE 把进程杀掉，**JSON 没落盘**，
  白跑一轮还看不出原因。长时间跑批一律写日志文件，不接 `head`。

## 四、关键词法的失效模式（为什么它只作佐证）

实测两法分歧很大，且**两个方向的错都出现过**：

| 方向 | 例子 |
|---|---|
| **假阳性** | 荆轲刺秦的「蓟城」「辽东」是燕国地名，属常识。`isolated` 档照常提到，关键词法判 100% 污染，Judge 判 0% |
| **假阴性** | 桃园结义 `shared` 档写"欲往许都投曹孟德"命中「许都」；但同档也有段落用"投曹公""往依之"等改写表达，一个标记词都不命中 |

**词面重合与"主角是否真的进了乙分支的设定"是两件事。** 关键词法便宜、可复算，
适合当粗筛；判定必须看 Judge。报告里两列并列，正是为了让这个分歧可见 ——
而不是把关键词法包装成一个有效指标。

> 这一节是刻意写的。本项目已经因为「一个看起来合理的指标其实在测别的东西」
> 吃过一次大亏。所以引入新指标时把它的失效模式一并写明，而不是只报对自己有利的那一列。

## 五、结果

这一节按**设计迭代的顺序**写，因为两次设计给出的结论完全不同，而差异本身就是结论的一部分。

### 5.1 v1 设计与其失败（12 组 × 3 轮）

v1 的分叉点都是"著名历史时刻 + 两种走向"。结果：

| 档位 | Judge 污染率 |
|------|------:|
| 分支隔离（本文） | 13% |
| 单线记忆（SCORE/DOME 式） | 37% |

净泄漏增量 24pp，配对 t = 1.75（df=11，临界值 2.201）→ **不显著**。

**更糟的是逐组拆开后的图案**：

| 组 | 乙分支是不是历史真实结局 | 单线档污染率 |
|---|---|------:|
| 桃园结义（投曹操） | 是（后来真投了） | 93% |
| 荆轲刺秦（燕退守辽东） | 是（就是史实） | 87% |
| 赤壁之战（孙权纳降） | 是（当年真争论过） | 53% |
| 张骞出使西域（娶妻留居匈奴） | 是（史实） | 13% |
| 其余 8 组 | **否** | **0%** |

污染**只出现在 4 组上，而那 4 组的乙分支全都是历史真实结局**。其余 8 组两档都是 0%。

这不是测量失灵 —— 关键词法在那 8 组里命中 12–15 次，但全是「渡河」「建康」这类
通用词的假阳性，Judge 判 0 是对的。**是模型压根不肯写违背史实的乙分支。**

> **结论：v1 测的是「记忆能不能压过模型先验」，不是「分支隔离有没有用」。**
> 这是设计缺陷，不是模型的问题。

### 5.2 v2 设计：把先验这个混淆去掉

改法：**让每组的两侧都不是标准历史**，模型没有先验可依赖，只能由记忆决定。

| 故事 | 分支甲 | 分支乙 |
|------|------|------|
| 桃园结义 | 向公孙瓒借兵 | 向陶谦借兵 |
| 张骞出使西域 | 先至大宛 | 先至乌孙 |
| 荆轲刺秦 | 割督亢之地 | 割辽西之地 |
| 赤壁之战 | 以周瑜统军 | 以程普统军 |
| 郭子仪单骑退敌 | 遣仆固怀恩 | 遣李光弼 |
| 完璧归赵 | 恃强不割城 | 依约割城 |
| 鸿门宴 | 命樊哙断后 | 命夏侯婴断后 |
| 卧薪尝胆 | 以范蠡主政 | 以文种主政 |
| 破釜沉舟 | 先攻甬道断粮 | 先攻王离解围 |
| 三顾茅庐 | 先图荆州 | 先图益州 |
| 苏武牧羊 | 遣卫律劝降 | 遣李陵劝降 |
| 淝水之战 | 以谢玄为帅 | 以谢石为帅 |

各组的两侧都**有史料依据、但都不是无争议的"标准答案"**（例：赤壁当年周瑜与程普
同为都督；苏武被扣期间卫律与李陵先后都去劝降过）。因此模型无法靠先验决定写哪个，
只能反映检索空间里有什么。

### 5.3 v2 主结果（12 组 × 3 轮，共 360 段）

| 档位 | 关键词法污染率 | **Judge 法污染率** | 两法一致率 | 各轮 Judge |
|------|------:|------:|------:|------|
| **分支隔离（本文）** | 57% | **19%** | 58% | 12% / 22% / 23% |
| **单线记忆（SCORE/DOME 式）** | 66% | **50%** | 80% | 62% / 47% / 42% |

### ➜ 净泄漏增量 = **31 个百分点**

配对 t 检验（配对单位 = 故事，n = 12）：

```
均值差 0.311   标准差 0.363   SE 0.105
t = 2.97     df = 11     双尾临界值 2.201   →  ✅ 显著 (p < 0.05)
```

**逐故事支配关系**：**10 胜、0 平、2 负**。

| 三顾茅庐 | 先图荆州 | 先图益州 | 20% | 40% | ✅ |
| 破釜沉舟 | 先攻甬道断粮 | 先攻王离解围 | 27% | 33% | ✅ |

```
                     遂令简雍先行，持密书往徐州探问陶谦意向……

```

分支甲的记忆里写的是"向公孙瓒借兵、驻扎北平"，而单线档的续写整段跑到了徐州投陶谦 ——
这正是乙分支的设定。

### 5.4 两处反转与它们的含义

张骞、苏武两组隔离档反而更脏（33% vs 27%、67% vs 27%）。

- **苏武牧羊**：隔离档 67% 明显偏高。分支甲是"遣卫律劝降"，但**卫律与李陵在史实中
  先后都出现过**，模型可能把两人都写进来 —— 这属于**标记与判定的边界情况**，
  不是隔离失效。
- **张骞出使西域**：33% vs 27%，差距在噪声范围内。

这两组提示：**当两条分支的实体在史料中本来就共现时，隔离的收益会消失**（模型靠
先验就能同时提到两者）。这是该方法的**边界条件**，应如实写进论文。

### 5.5 结论

**能说**：

1. 单线记忆系统下，分支甲的续写有 **50%** 的段落采用了分支乙的设定；
   分支隔离压到 **19%**。净泄漏增量 **31 个百分点**，配对 t = 2.97（df=11，p<0.05）。
2. **核心创新「分支感知」有统计支撑** —— 这是本论文相对 SCORE / DOME 的增量贡献。
3. 逐故事 **10 胜 0 平 2 负**。

**不能说 / 需注意**：

1. 效应**依赖于分叉设计**：v1（两侧含标准历史）只有 12pp 且不显著，v2（两侧均非标准历史）
   才有 31pp。论文必须说明这一点 —— **分支隔离的收益在"模型没有强先验、必须依赖记忆"
   的场景下才显现**，这既是边界条件也是合理的适用条件。
2. 12 组里 2 组出现反转，且反转都发生在"两分支实体在史料中本来共现"的设定上。
3. 关键词法与 Judge 一致率只有 58%（隔离档），关键词法的假阳性问题见 §四。

### 5.6 ⚠️ 数据完整性

- **v2 正式结果**：3 轮全部完整（各 24/24 组合），无 API 错误。
- 中途因**机器重启**中断过一次（v2 首轮跑到 17/24），已归档为 `.partial` 排除。
  脚本已改为**增量落盘 + `.json.wip` 完成标记**，半截轮不会被误当成完整轮。
- 汇总范围修复：早先默认会把 `n5` / `n12` / `n12_v2` **三代设计平均在一起**
  （报告一度显示"10 轮实验"、逐故事表混着旧版标签）。现默认只汇总本次设计
  （文件名前缀 `branch_isolation_n{组数}[_tag]_`），跳过的文件数会打印出来。

> 📌 **一句话给论文用**：在 12 组"两侧均非标准历史"的冲突分叉上，分支隔离把跨分支
> 事实泄漏从 **50% 压到 19%**（净 31 个百分点，配对 t = 2.97，df = 11，p < 0.05），
> 逐故事 10 胜 0 平 2 负；而在含标准历史的 12 组上效应仅 12pp 且不显著 ——
> **收益取决于模型是否必须依赖记忆**。
