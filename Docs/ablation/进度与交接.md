### 两条确认性结论（附各自的适用条件）

| 实验 | 效应 | 规模 | 校正后 |
|---|---|---|---|
| A `state` 记忆注入降低退化复读 | 53.3% → **25.6%** | 30 故事 × 3 轮，配对 df=29 | ✅ t=−3.62，p=0.0011（过最保守 k=4 的 2.663） |
| A `both`（状态表 + 图谱） | → **17.8%** | 同上 | ✅ t=−4.98，p<0.0001 |
| A `graph`（仅图谱） | → 41.1% | 同上 | ❌ t=−1.61，p=0.118，连未校正的 2.045 都没到 |
| B 分支隔离抑制跨分支污染 | 50% → **19%** | 12 组 × 3 轮，配对 df=11 | ✅ t=2.97，p=0.0127（临界 2.820） |

📌 **实验 A 的适用条件（论文必须写）**：收益大小约等于「这个故事原本有多糟」的镜像 ——
基线 33% 与 83% 的两组故事，在 `state` 档分别落到 28.2% / 26.2%。
合并显著性几乎全部来自第一批（基线 64.4%），第二批（基线 42.2%）t=−1.15。
**基线是调节变量，批次不是**（协变量校正后批次系数 p=0.40/0.70/0.45）。
已决定**不再补第三批 15 个故事**。

📌 **实验 B 的适用条件（论文必须写）**：效应**依赖分叉设计** ——
v1（含标准历史结局）只有 24pp 且 t=1.75 不显著；v2（两侧都改成非标准历史）
才测到 31pp。**分支隔离的收益在「模型没有强先验、必须依赖记忆」的场景下才显现。**

📌 **实验 A 的样本量是照着功效分析定的**（15 故事时按观测效应量反推需 26–29 个故事，
扩到 30 后如预测转显著）。这是全稿唯一一条「先预测、后验证」的结论，
论文里值得强调这个顺序 —— 它和「跑完再看」性质不同。

## 二、六条被数据推翻的假设（完整表格见论文实验章 §5）

1. ❌「`state` 档抑制退化复读」—— 重跑即翻转，指标是双峰的
2. ❌「图谱注入是负贡献」—— 实为"无效"而非"负贡献"
3. ❌「两模块互补，`both` 最优」—— 5 故事成立，15 与 30 故事均未复现
4. ❌「分支隔离净减 24pp」—— 拆开发现效应只来自 4 组（乙分支=史实），是混淆
5. ❌（后被扩样救回）「两条主线均达统计显著」—— 校正后不成立；
   扩到 30 故事后重新显著，但这次是照功效分析扩样取得的，性质与第一次不同
6. ❌「实验 A 效应增强来自种子数据修复」—— s15 vs s30 同一批 15 故事做差分再差分，
   三档 p=0.22/0.32/0.27 且变化量几乎相同（共模）。**改过某个东西 ≠ 就是它造成的**

**由此得出的检验清单**：双峰指标要先看分布；n<10 的排序不可信；效应若集中在子集
就是有混淆变量；度量工具必须确定性（LLM-as-Judge 温度锁 0）；加轮次只降噪、
不增样本量，要显著性必须加**故事数/分叉数**；一次分析里做多个比较就必须做多重比较校正；
合并样本显著后要拆批次与协变量；**归因之前先做差分再差分**。

## 三、实验 B 的台架与刺激材料（踩过的坑）

### 3.1 台架 bug：`isolated` 档曾经根本没隔离干净（2026-10-06 已修）

`Character`（角色登记表）是**故事级**的、**没有 `branchId`**，而 `buildMemoryReminderPrompt`
会把登记到的名字以**「必须逐字原样使用，禁止替换、简写、形近字替代」**写进 Prompt 的
**硬约束块**。`setupFork` 原来无条件登记甲、乙两分支的角色 →
隔离档的 Prompt 里照样出现乙分支的人名。

修法：加 `isolation` 参数，只在 `shared` 档登记乙的角色。
复跑确认（`branch_isolation_n1_recheck_*`）隔离档「已知角色名」里已无乙的人名。

> **一般性结论：「按 `branchId` 过滤」这条原则在代码里不是处处成立的。**
> ✅ 状态表（`narrative_states_${branchId}` 键名空间）、知识图谱（节点/边带 `branchId` 字段）
> ❌ **角色登记表 `Character`**、**导演状态 `DirectorState`（`storyId @unique`）**
> 后两处已写进论文稿 §2.9-1、§2.9-2 作为已知局限。

### 3.2 marker 的选择标准：不是"正史与否"，而是**显著度**

marker 必须是**模型只看到公共前文时不会主动写出**的字符串，否则关键词法把模型的先验
当成泄漏（假阳性）。**只看乙分支的 marker**（甲分支的 marker 只需不出现在 opener 里）。

反例（都是"模型先验里可及"的）：

| 故事 | marker | 为什么不行 |
|---|---|---|
| 垓下之围 | 周殷 | 项羽麾下在场将领，模型自己就会写；更糟的是被角色登记表直接写进 Prompt |
| 马嵬坡 | 褒斜 | 秦岭最著名的栈道 |
| 郑和下西洋 | 柯枝 | 宝船队常规经停港 |

**用地名而不用人名通常更安全，但名人名场面里的著名地名同样不安全。**

### 3.3 四个早已修掉的设计缺陷（详见 [跨分支污染实验.md](跨分支污染实验.md) §三）

① 分叉点 opener 把两个选项都写出来了 ② 拿著名历史人物当标记词
③ 标记词是通用词 ④ Judge 的采样温度没锁（**度量工具本身是随机的**）

## 六、环境备忘

```bash
docker compose up -d postgres     # 独立脚本需要数据库（映射在 localhost:5433）
npm test                          # 全部测试（vitest + 独立 tsx 脚本）
npx tsx tests/ab_branch_isolation.ts --stories=20 --segments=5 --rounds=3 --out=branch20_rounds_report.md
npx tsx tests/ab_ablation.ts --report-only        # 不重跑 AI，用最新结果重建报告
npx tsx tests/ab_robustness.ts                    # 复用已有 JSON 做稳健性分析
```

`.env` 用 DeepSeek（`AI_BASE_URL=https://api.deepseek.com/v1`）。
`[AIRequestQueue]` 有 **20 次/分钟**限流，扩样跑多轮时会被限速，属正常现象。

### ⚠️ 跑批必须用独立进程

跑批要一小时以上，**挂在 Claude Code 会话上的后台任务会随会话结束被杀**（踩过三次）。
用 `run_*.bat` + `Start-Process` 起独立进程；机器休眠也要关
（`powercfg /change standby-timeout-ac 0`，用 `powercfg /query` 确认索引 0x0）。

### ⚠️ 汇总口径

报告默认只汇总**本次设计**的结果文件（按文件名前缀 `branch_isolation_n{组数}[_tag]_` 匹配），
跳过的文件数会打印出来 —— 早先默认会把 n5 / n12(v1) / n12(v2) **三代设计平均在一起**，
报告一度显示"10 轮实验"却看着完全正常。要显式混跑用 `--only`。
半截轮落 `.json.wip`，达标才改名，不会被误当成完整轮。

**图片 API Key 是占位符 `your-a...`**，生图链路只有单测覆盖，没有实跑验证过。
