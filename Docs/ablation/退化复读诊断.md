# 退化复读诊断：「相邻段重复度」这个指标为什么不能用

> 2026-09-14 ｜ 结论先行：**该指标是双峰的，被稀疏的"整段照抄"事件支配。**
> 它测的是"这次有没有抽到复读"，不是"这一档的记忆注入好不好"。
> 必须拆成「退化复读率」+「非退化中位数」两个量报告。

---

## 一、怎么发现的

重跑同一份代码（`none` / `state` 两档的 Prompt 构造路径在两轮之间**没有任何改动**），
档位排名整体翻转：

| 档位 | 轮 1（09-13） | 轮 2（09-14） | 轮间差 |
|---|---:|---:|---:|
| `none` 无记忆 | 0.332 ± 0.307 | 0.127 ± 0.216 | **0.205** |
| `state` 仅状态表 | 0.043 ± 0.022 | 0.233 ± 0.151 | **0.190** |
| `graph` 仅知识图谱 | 0.254 ± 0.302 | 0.324 ± 0.312 | 0.070 |
| `both` 状态表+图谱 | 0.177 ± 0.257 | 0.240 ± 0.182 | 0.063 |

`state` 从"最好"变成"比基线还差"。轮 2 的档间最大差是 0.11，**轮间差（0.19–0.21）比档间差还大**。

因为 `none` / `state` 两档根本不注入图谱，它们的 Prompt 代码路径两轮完全一致——
这个摆动只可能来自模型侧。于是去查数据本身。

## 二、指标是双峰的

把 20 个相邻对的相似度全部摊开看，不是连续分布，是**两簇**：

- 绝大多数落在 **0.01–0.15**（正常续写：情节推进、用词不同）
- 少数**恰好 1.00**

查 1.00 那些相邻对的原文——它们是**逐字节完全相同**的段落：

```
段3 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…
段4 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…
段5 (367字): 秦王既诛荆轲，怒犹未息，乃诏群臣议伐燕之策。丞相李斯进曰：…

段3 与 段4 完全相同? true
```

所以 1.00 的含义不是"情节套路化"，而是**模型整段照抄了上一段**——一个明确的生成失效。

## 三、两个放大机制让它彻底压过真实差异

### 1. 一个触发点贡献多个 1.00（吸收态）

照抄出来的文本又成为下一段的"上文"，模型继续照抄。上例中段 3/4/5 全同，
4 个相邻对里有 **2 个**是 1.00 → 该故事均值从 ~0.05 直接抬到 **0.512**。
一个触发点 = 一个故事的均值被毁掉。

### 2. n 太小

n=5 故事时，一个故事触发就把该档均值抬高约 **0.1**——已经超过档间真实差异。

## 四、排除了台架 bug（关键）

"不同 Prompt 产出逐字节相同的文本"太反常，所以专门验证了是不是代码问题。
诊断脚本 [repro-repeat.ts](../../scripts/repro-repeat.ts) 逐步打印 Prompt 哈希与正文哈希：

```
═══ 第 3 轮 ═══
步骤  PromptLen  PromptHash     正文字数  正文Hash      与上段相同
   4       2814  c129b59a8bd6      277   7bd7b4c2ba55
   5       3098  f95189dae53d      277   7bd7b4c2ba55   ✅ 完全相同
```

复读发生时，**Prompt 内容哈希与长度都变了**（2814→3098），输出却逐字节相同 → 不是台架 bug。

另外单独验证采样确实是随机的：同一 Prompt 连调三次，输出互不相同。
所以这不是"温度设成了 0"之类的问题，是模型在特定上下文下进入的照抄吸引子。

**发生率**：3 轮 × 6 段 = 18 步中出现 1 次 ≈ **5%/步**，且哪一轮触发是随机的
（第 3 轮触发，第 1、2 轮没有）。

## 五、它和记忆档位无关

按故事×档位统计"是否触发过复读"（两轮共 4 次机会）：

| 故事 | 触发次数 | 说明 |
|---|---:|---|
| 荆轲刺秦 | **4 / 4** | `none`/`graph` 两档、两轮都触发 |
| 郭子仪单骑退敌 | 1 / 4 | |
| 赤壁之战 | 1 / 4 | |

而且两轮之间**没有任何一段正文文本相同**（共有段文本 = 0/3、0/2、0/5），
说明触发不是确定性的，但**「荆轲刺秦」这个故事的触发倾向明显更高**（4/4）——
是故事级的性质，不是档位级的。

> 可能的原因：荆轲刺秦的起始片段已经写到"荆轲已死"，续写缺乏可推进的目标，
> 模型倾向于把上文当结论复述。这值得单独查，但不影响本文档的结论。

## 六、结论与改法

**结论**：退化复读是模型侧的固有失效模式，与记忆注入无关，约 5%/步。
把它混进"相邻段重复度均值"里当被解释变量，等于让噪声支配结论。

**改法**（已落地在 `tests/ab_ablation.ts`）：

1. 指标拆成两个量报：
   - **退化复读率** = 相似度 > 0.9 的相邻对占比 → 反映稳定性，越小越好
   - **非退化中位数** = 剔除退化对之后的中位数 → 反映正常的段间相似度
   - 均值仍然打印，但标注为"不可单独下结论"
2. 报告 §二 每个故事标出 `⚠️ 退化对数`，让读者一眼看到均值是被什么抬起来的
3. 修掉 `--report-only` 的一个取数 bug：原按文件名字典序取"最新"，
   `ablation_results_2026-…` 排在 `ablation_results_full_5x5.json` **前面**，
   会取到旧数据。改为按 `mtime` 排序。

**拆开之后两轮数据的真实面貌**（中位数，列 1 = 轮 1，列 2 = 轮 2）：

| 档位 | 非退化中位数（轮1 / 轮2） | 退化复读率（轮1 / 轮2） |
|---|---|---|
| `none` | 0.031 / 0.026 | 0.25 (5/20) / 0.10 (2/20) |
| `state` | 0.034 / 0.035 | 0.00 (0/20) / 0.15 (3/20) |
| `graph` | 0.030 / 0.031 | 0.20 (4/20) / 0.30 (6/20) |
| `both` | 0.031 / 0.029 | 0.10 (2/20) / 0.10 (2/20) |

**中位数在两轮之间高度一致（0.026–0.035），且四档之间没有可见差异。**
这才是数据实际说的话：在当前样本量下，**记忆注入对相邻段相似度没有可检出的影响**。

## 七、对论文的影响

1. 之前"`state` 档抑制退化复读（5 个故事 0 次 1.00）"的说法**作废**——
   轮 2 里 `state` 退化率 0.15，比 `none`（0.10）还高。那是运气。
2. 4 档消融的**排名不可用**，`both` vs `state` 的优劣**目前无法判定**。
   早先基于轮 1 得出的"图谱注入是负贡献"这一结论，证据不成立
   （修复本身仍然正确——注入重复/自相矛盾的内容当然该删，只是它的
   效果在这个指标上测不出来）。
3. 需要在论文里（a）把这个失效模式作为**独立发现**报告，
   （b）在剔除退化对之后比较各档，（c）扩样到每档 ≥3 轮再谈差异。

> 反向看，这其实是个可利用的点：**"记忆注入能否降低退化复读率"本身就是一个
> 干净的可测假设**，而且退化复读是明确的生成质量缺陷，比"相邻段相似度"
> 这种代理指标更适合放进论文当被解释变量。
