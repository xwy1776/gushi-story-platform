## 五、🔴 找到一个机制：胡须漂移的成因

章真毓在三次实验里都观察到「胡须漂移」，并把它列为第一行动项但未做。
这次复验定位到了机械成因。

一致性要求块（每条 prompt 都注入）写的是：

```
Fixed character design — must stay identical in every image of this story
(same face shape, same facial features, same facial hair, same body build, same hair, same outfit)
```

而荆轲的角色规格（`scripts/image-face-consistency-experiment.ts:81`）是：

```
Jing Ke: male, early 30s, lean weathered face, short black hair in a topknot,
         dark brown hanfu robe, leather forearm bracers, dagger at waist.
```

**规格里没有胡须。** 逐项对照锚点要求的六个字段：

| 锚点要求的字段 | 规格里有没有值 |
|---|---|
| same hair | ✅ `short black hair in a topknot` |
| same outfit | ✅ `dark brown hanfu robe, leather forearm bracers` |
| same body build | 🟡 只有 `lean` |
| same face shape | 🟡 只有 `lean weathered face` |
| same facial features | ❌ 没有具体值 |
| **same facial hair** | ❌ **完全没有** |

**机制**：锚点要求「胡须保持一致」，却没有给出胡须**是什么**。
模型每次只能自己编，而编出来的值不受任何约束；各段的场景 prompt 又不同
（stable 组三段分别 1039 / 1071 / 1194 字符），采样轨迹就不同 ——
于是这个「无值字段」自由漂移。

> **一句话：锁 seed 锁得住「有值的东西」，锁不住「没值的东西」。**
> 锚点只能约束它拿到了值的字段；对没有值的字段，它输出的只是一句
> 「请保持一致」的空要求，反而制造了不确定性。

**修法**（与 §六 那张待办里「补须式字段」是同一件事）：
把锚点的六项**从「要求一致」改成「给出值」** ——
规格里没有的字段，要么补上具体描述（如 `facial hair: short black beard and moustache`），
要么**从锚点要求里移除**（要求一个不存在的字段一致，只会制造不确定性）。
前者更好：它把「须式」变成一个真实被约束的属性。

> 这一条**不依赖生图 API Key，现在就能改、能用 `--dry-run` 验证** ——
> 改完重跑一次 dry-run，看锚点块里是否出现了具体的胡须描述即可。
